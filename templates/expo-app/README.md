# Verdict app template (Expo SDK 58)

One template, many apps. Each studio venture is this project plus two generated files:
`spec.json` (the product: onboarding, core AI action, paywall, share card, push schedule)
and `studio.json` (identity, URLs, store products, env var names, privacy manifest). The
builder (`src/builder/render.ts`) copies the template and writes both files. Do not
hand-edit a rendered copy; change the spec or this template instead.

## What the builder writes

For a venture with slug `<slug>`, `renderApp` produces `<outRoot>/<slug>/`:

| Path | Contents |
|---|---|
| `app/` | this template (without `node_modules`, `.expo`), plus `spec.json`, `studio.json` |
| `app/server/tenants/<slug>.json` | the verdict backend's tenant: composed system prompt (fixed safety preamble, domain rules, then the product prompt), output sections, free uses, entitlement, rate limits |
| `app/assets/icon.png` | written by the brand agent, preserved across re-renders |
| `store/metadata/<locale>/*.txt` | listing fields in fastlane `deliver` layout |
| `store/screenshots/<n>.png` | upload-ready 1290x2796 RGB PNGs, nothing else |
| `store/screenshots-src/<n>.svg` | the screenshot sources |
| `store/app-privacy.json`, `store/data-safety.csv` | App Store privacy answers and Play Data safety, derived from the data inventory |
| `ios/PrivacyInfo.xcprivacy` | the privacy manifest; it lives outside `app/` so EAS keeps running prebuild (the same manifest reaches the binary through `ios.privacyManifests`) |
| `legal/privacy.md`, `legal/terms.md` | policy and terms from fixed clauses (never LLM-written) |
| `site/` | landing, privacy, terms, support, the share-link fallback page and `.well-known/` association files |

## App structure

* `app/_layout.tsx` starts up: PostHog, then RevenueCat with the PostHog distinct id as the
  app user id, then experiment flags and remote config, then launch events and reminders.
* `app/index.tsx` routes by stored onboarding state and the paywall placement.
* `app/onboarding.tsx` renders every `OnboardingStepKind` from the spec. The AI-data consent
  step names the providers that receive the user's input (Apple 5.1.2(i)). The notification
  pre-prompt asks the OS for permission only after the user taps Yes; promotional reminders
  need the separate opt-in toggle (Apple 4.5.4).
* `app/paywall.tsx` resolves products from RevenueCat offerings by store product id
  (`<bundleId>.<ladderId>`). The terms line next to the button comes from the store
  product's localized price, period and intro trial (`src/terms.ts`, same wording as the
  studio's `termsTemplate`). Restore, Manage subscription, Terms and Privacy are always
  shown. The close button appears after `showCloseAfterSeconds`.
* `app/home.tsx` takes the input for `core.inputKind` and posts it to `/v1/verdict`.
* `app/result.tsx` shows the sections under a persistent "Generated by AI" notice, offers
  Report this result, and shares a captured card with the watermark and deep link.
* `app/settings.tsx` has restore, manage subscription, AI consent, promotional reminders,
  delete my data, legal links and support email.

`src/events.ts` copies the studio's canonical event names and `src/types.ts` mirrors the
spec contracts; the builder's tests fail if either drifts. The app never requests
tracking: no App Tracking Transparency prompt, no IDFA, and Android's `AD_ID` permission
is blocked.

## Environment

EAS build environment (public client keys; the variable names are listed in `studio.json`):

* `EXPO_PUBLIC_POSTHOG_API_KEY`, `EXPO_PUBLIC_POSTHOG_HOST`
* `EXPO_PUBLIC_REVENUECAT_IOS_KEY`, `EXPO_PUBLIC_REVENUECAT_ANDROID_KEY`

Build profiles (`eas.json`): `development` (dev client), `preview` (internal), `production`
(store). Build numbers auto-increment remotely; the version string comes from `studio.json`.
Updates use the fingerprint runtime policy.

## Verdict backend (`server/`)

One deployment serves every app; each app is a file in `server/tenants/`. Copy each
rendered `tenants/<slug>.json` into the deployed service's tenants directory.

```
cd server && npm install && node src/index.ts      # Node >= 22.18
```

Env: `ANTHROPIC_API_KEY`, `PORT` (default 8080), `TENANTS_DIR` (default `./tenants`) and one
RevenueCat secret key per app under the name its tenant file lists in
`revenueCatSecretEnv` (e.g. `REVENUECAT_SECRET_KEY_ASTRA`).

Endpoints: `POST /v1/verdict`, `POST /v1/report`, `POST /v1/delete`, `GET /v1/config`,
`GET /healthz`. A verdict request is refused without AI consent, rate-limited per user,
allowed for the tenant's free uses and otherwise only with an active RevenueCat
entitlement. Claude is called with the official SDK at low effort and a JSON schema for the
sections; refusals and blocklisted output return a neutral error instead of the text.
Usage counts, rate limits and the entitlement cache are in memory, so run one instance per
deployment or put them in a shared store before scaling out.
